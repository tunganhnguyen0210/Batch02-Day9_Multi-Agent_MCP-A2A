Phương Án Giảm Latency
1. Prompt Caching (Anthropic)
Dùng cache_control breakpoints trên system prompts dài. Các LLM call lặp lại cùng system prompt sẽ tái sử dụng cached tokens thay vì recompute.

cache_control: {"type": "ephemeral"}
↓ ~40-60% TTFT cho specialist agents
2. Parallel Specialist Dispatch
Đã implement với LangGraph Send API (Stage 4) và asyncio.gather (Stage 5). Tax + Compliance chạy đồng thời thay vì tuần tự, tiết kiệm thời gian bằng agent chậm nhất.
↓ ~2.5s (từ 5s → 2.5s cho specialist phase)
3. Streaming Responses
Dùng astream() thay vì ainvoke() để trả về từng token ngay khi LLM sinh ra. User nhận được kết quả bắt đầu sớm hơn ~1-2s.
↓ TTFB từ ~4s → <0.5s (perceived speed)
4. Model Tiering
Dùng model nhỏ hơn (claude-haiku-4-5) cho check_routing và các bước đơn giản. Chỉ dùng claude-sonnet cho synthesis và phân tích phức tạp.
↓ ~0.8s cho routing node (Haiku 3-5× nhanh hơn Sonnet)
5. Connection Pooling
Tái sử dụng httpx.AsyncClient giữa các A2A calls thay vì tạo connection mới mỗi lần. Giảm TCP handshake overhead cho distributed stage 5.
↓ ~0.1-0.3s per A2A hop
6. Registry Cache
Cache kết quả discover() trong bộ nhớ với TTL 60s. Tránh HTTP call đến Registry cho mỗi request khi agents không thay đổi.
↓ ~0.05s per request (small but free)
Before optimization (sequential, no cache) ~8.5s
After: parallel + haiku routing + prompt cache ~2.8s
